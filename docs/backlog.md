# Backlog

Tasks for phases 1 and 2 of the MVP (see "Milestones" in [spec.md](spec.md)). Tick items off as they land; add new ones where they belong. **[Owner]** marks tasks only Josh can do; everything else is code Claude Code can pick up. Each task names the package or service it lives in and should fit in one session; split it if it doesn't.

The stack was decided on 2026-10-12: see ADRs [0006](decisions/0006-typescript-backend.md) to [0009](decisions/0009-hosting-and-budget.md), with background in the [stack review](reviews/2026-10-12-stack-review.md). Through Phase 3 everything runs on the owner's Windows PC (Docker Desktop on WSL2). In Phase 1 bundles and session recordings reach the PC over USB; from Phase 2 the phone uploads over home Wi-Fi on the LAN.

The MVP is the Esplanade corridor (owner decision, 2026-10-17; [spec](spec.md#mvp-scope-the-esplanade-corridor)): South Beach to Raffles City through Esplanade MRT's unpaid B1 level, Raffles City's link to City Hall MRT's unpaid concourse, and Marina Link to Marina Square's door. The former City Hall cluster (Funan, the rest of City Hall MRT, CityLink) is the first expansion after the MVP. Scope: [0011](decisions/0011-mvp-scope-esplanade-corridor.md). Capture recording and replay were decided the same day ([0010](decisions/0010-capture-recording-and-replay.md)).

Test fixtures: the repo will be public. Fixtures in git are synthetic, recorded where the owner is happy to publish them (with no images or GNSS fixes), or images used with the subject's consent or under an open licence. Nothing recorded in a venue goes in git (meshes, pose tracks, keyframes, session recordings, `restricted_zones` outlines): keep it in the git-ignored `.data/fixtures/`, and tests that need it skip when it is absent. Only committed fixtures run in CI. Claude Code runs the tools on data the phone recorded, from any build, but never reads its raw contents or copies it outside `.data/`: the tools print aggregate results only ([CLAUDE.md](../CLAUDE.md)).

  - Done when: a pilot-sized bundle uploads over home Wi-Fi, carries on with the app in the background, and completes on the server
- [ ] Recording upload over the LAN (`services/api`, `apps/mapper`, `scripts/`): owner-only, to a private `usg-recordings` bucket (never `usg-bundles`; added to `pnpm buckets`), after the device token and the multipart upload. The route refuses requests that arrive through the tunnel
  - Done when: a recording's export uploads over the LAN, and the same request through the tunnel is refused
- [ ] Validation job (`services/processing`): fetch the bundle from private storage, run the validator, set `captures.status` and `failure_reason`
- [ ] Privacy re-check (`services/processing`, worker process): YuNet faces through onnxruntime-node, run on tiles or at several scales. A frame with a still-sharp face (variance-of-Laplacian test inside the detection) is quarantined: removed from the stored bundle and excluded from processing; its frame index goes into `captures.quarantined_frames` and `captures.privacy_flagged` is set, which blocks publishing until the owner or a moderator clears it. The bundle fails (`captures.status = 'failed'`, `failure_reason = 'privacy'`) and is deleted only if the quarantined share exceeds the threshold (a tuning value, starting at 5%) or an anchor photo is affected
  - Decode keyframes with a pixel limit (for example sharp's `limitInputPixels` at the validator's `maxImagePixels`), and treat a keyframe that can't be decoded as a failed check, never as a pass
  - `pnpm rec import` uses the same re-check over every image in a replay set, and a quarantine or privacy failure here is carried over to the fixture copies by `capture_id` ([0010](decisions/0010-capture-recording-and-replay.md))
  - Done when: fixture tests cover a quarantined frame, a failed bundle and an affected anchor photo, and a stored bundle with quarantined frames still validates
- [ ] Screen re-check (`services/processing`): add a permissively licensed screen detector to the re-check (chosen in this task; the stack review suggests RT-DETR, Apache-2.0), and decide what a still-sharp screen does: quarantine like a face, or flag for review, since the server model also finds displays the phone rightly left sharp. Record both in [0005](decisions/0005-privacy-by-design.md); the ONNX export is offline tooling
  - Done when: a still-sharp screen fixture gets the chosen outcome
- [ ] Trajectory clean-up (`services/processing`): drop frames with `limited` tracking, split at relocalization jumps, and use `refined_keyframes.jsonl` transforms where present
- [ ] `pnpm rec pipeline` (`packages/recording`, `services/processing`): a replay set's bundles through validation, the privacy re-check, trajectory clean-up, the network adjustment, extraction and the diff, against a scratch database copied from the migrated template, with the venue's restricted zones loaded from `db/private/`. Output in `.data/replays/` only, never test goldens. A `test:venue` case per processing task
  - Done when: a synthetic set runs end to end, and extraction clips against a synthetic zone
- [ ] Backups (a script beside `docker-compose.yml`): raw bundles, recordings, the private full exports (`private_export_uri`) and a database dump to an external drive or a cheap S3 bucket in ap-southeast-1 (the owner picks which). Encrypted at rest either way, for example BitLocker on the drive and server-side encryption on S3. It honours `pnpm rec delete`'s deletion list and keeps backup sets at most 30 days, so a deletion reaches every copy within that time ([0010](decisions/0010-capture-recording-and-replay.md))

### Alignment (`services/processing`)

- [ ] Street priors: propose priors for street-facing anchors from LTA exits (`lta_exit`) and GNSS fixes (`gnss`), as anchor diff entries in the change set (`surveyed_geom`, `prior_source`, `prior_sigma_m`); they reach `anchors` only on approval ([0008](decisions/0008-anchors-and-georeferencing.md)). Placement on imagery (`imagery`) by the owner is the fallback. A connected group needs at least two widely spaced street priors before it can be published
- [ ] Network adjustment solver (worker process): unknowns x, y, z and yaw per anchor; one relative constraint per segment between its anchors (sigma about 1% of the distance walked); street priors as absolute priors with metre-level sigma; level elevations as soft height priors; Gauss-Newton on a small dense system, in SVY21
  - Done when: it recovers a known transform for a chain of 4 synthetic segments where only the two ends have street priors, using real corridor coordinates (Esplanade Exits F and C and the Raffles City door)
- [ ] Apply the solution: write `segment_alignments` (each segment's transform and the residuals at its start and end anchors), and store each anchor's solved position and yaw and its residual against its street prior (where is decided in this task; record it in [0008](decisions/0008-anchors-and-georeferencing.md) with a migration). Spread each segment's end correction along the walk by cumulative distance, and apply it to the ARKit mesh (no re-meshing). Convert to WGS84 with `ST_Transform`

### Extraction and diff (`services/processing`)

- [ ] Restricted zones for the corridor's venues (`db/`): load the outlines noted on the site walk into `restricted_zones`, from a file kept out of the public repo (the git-ignored `db/private/`, or private storage). Tests use synthetic zones
- [ ] Extraction v0: floor polygons from the corrected floor faces; centreline edges from the corrected walk path, with tag nodes snapped onto it; level floor heights into `levels.elevation_m`, relative to the datum floor. Everything is clipped against `restricted_zones`
- [ ] Conflation against HEAD: match extracted features by kind, level and proximity or topology (in SVY21) and keep existing IDs. New UUIDs only for genuinely new features
  - Done when: re-extracting a segment with one moved node gives a move in the diff, not a remove and an add
- [ ] Diff to `change_sets`: a diff in the `docs/diff-format.md` format, validated against its schema, with `base_version_id` set and `change_set_captures` rows. A feature that overlaps the interior of a `restricted_zones` polygon fails the restricted-zone gate and blocks publishing until it is fixed (the database also refuses it in HEAD)
- [ ] Change-set preview (`apps/web`): an owner-only route that draws a pending change set, the aligned segments and their residuals over OneMap tiles, from the local API. It grows into the moderation UI in Phase 4

### Field test

- [ ] [Owner] Walk the pilot segments with the walk build, during opening hours on a quiet weekday morning (shops open, few people), one session per leg within the safe session length, in the `standard` profile for walks meant as fixtures:
  - P1: Exit F's street door → the Exit F link → the B1 junction (about 30–70 m). Start anchor: a `floor_point` at Exit F's street door, with a GNSS fix and the LTA prior; end anchor: the floor point where the link meets the B1 corridor
  - P2: the B1 junction → west → the Exit G passage → the Raffles City B2 door threshold (about 150 m), out and back so drift can be measured
  - P3: the B1 junction → east → the Exit C (about 125 m) or Exit E (about 85 m) street door, with GNSS: a second street prior 90–140 m from Exit F
  - Then Marina Link: Exit B → Marina Link → Marina Square's basement door (about 100 m), before the mall closes on 31 Mar 2027
  - Anchors at door thresholds where the station meets a venue; image anchors only on unique signs (mall name boards, a directory board), since station exit signs repeat; avoid fare-gate lines, escalator landings and shopfronts, which change often in Esplanade Xchange. LTA priors only for exits that open at street level (not B or G)
  - If Exit F has no public street door of its own (site walk), P1 starts at the B1 end of the Exit F link instead, and the second street prior comes from Exit C or E
- [ ] Field-test write-up (`docs/`): drift and residuals per segment and per anchor, with `os_version` and `device_model` for each segment. Propose starting values for the drift threshold, "widely spaced" street priors (Exit F to Exit C, 131 m apart, is borderline; City Hall's Exits A and B, 240–360 m away, join the group when Raffles City's link is mapped) and the residual thresholds that gate publishing
- [ ] Decide on COLMAP from that data and record it in [0008](decisions/0008-anchors-and-georeferencing.md): switch it on only if more than about 20% of segments drift over 1 m, network residuals exceed 1–2 m, or overlays cross walls. If it is needed, add a task here for the containerised COLMAP 4.x / pycolmap step (driven by the job queue, ARKit poses as priors)

## Later phases

Phases 3 and 4 get broken down into tasks once the Phase 2 gate passes. Outlines for now.

### Phase 3: Map and routing

Gate: routes verified on foot.

- [Owner] Capture the rest of the corridor with the same capture rules: Raffles City's basement and its link to City Hall MRT's unpaid concourse, the rest of Esplanade's unpaid B1 level and its street exits, and South Beach's public basement as far as the pedestrian network goes. Marina Square's interior only if there is time before it closes on 31 Mar 2027
- `street_connectors`: join each exit and entrance to the nearest street vertex, computed in SVY21 and rebuilt inside each publish transaction
- `access` and `opening_hours` on edges, from the site-walk notes
- Router in `packages/routing`, used by `apps/web` and `apps/mapper`: cost in seconds from `routing-config.json`; excludes features closed in the status overlay, `paid_fare_zone` and `customers_only` edges by default, and edges whose `opening_hours` say closed at the time of travel (Asia/Singapore); step-free mode excludes stairs and escalators; a one-time lift boarding penalty; outdoor edges heavily penalised when "stay underground" is on
- Route search in `apps/web` between two street-level points
- Approval: run the automated gates and record the result in `moderation_events`; check each touched feature's `rev` and that the base version was not undone by a rollback (`needs_rebase` otherwise); apply the diff, bump revs, publish through the `owner_mapper` path. DB rule tests cover an `owner_mapper` publish with a failed gate. Public files go to Cloudflare Pages and R2 on free tiers. (The gates, the apply and the `owner_mapper` publish exist since Phase 1, in `services/api/src/publish/`; what remains is running them from the approval path and the R2 upload. The upload copies the directories that `map_versions` rows name, plus `latest.json` and `status.json`, never the whole bucket)
- Rollback: restore HEAD from a version's private export ([head-export-format.md](head-export-format.md)), refusing a restore that would delete a level or venue with restricted zones, and publish it as a new version with `restores` set and no change set; mark the undone versions' structural change sets `rolled_back`
- Check the street connectors' 100 m limit against the real exits once the OSM import runs, or split street edges at the nearest point instead of joining the nearest vertex
- [Owner] Walk the routes; tune `routing-config.json` from what the walks show
- [Owner] Set the retention periods for raw bundles and status evidence photos, before Phase 4 (recordings' retention is set: [0010](decisions/0010-capture-recording-and-replay.md))

### Phase 4: Locate and launch

Gate: public beta goes live.

- Localization (`services/localization`, Go): onnxruntime_go on CPU, MegaLoc retrieval, (RaCo-)ALIKED + LightGlue (LightGlue-ONNX exports), PoseLib through a cgo shim, built in a Linux container. A model allow-list in CI. The index is built per published version from approved captures only
- Models over about 50 MB are fetched at build time with a pinned checksum, never committed (GitHub rejects files over 100 MB)
- `POST /locate` with the privacy-path checklist and its no-temp-file, no-body-logging test; rate limits and a bounded queue. CPU benchmark on corridor data: 3 s is measured and reported, not a gate; a GPU only with the owner's approval
- An owner-only draft index on the server for testing a photo locate against the draft in mapper mode
- Contributor sign-up: email one-time codes plus passkeys (Better Auth is the likely library; confirm then), trust tiers, shared drafts (a server-side `drafts` table) and external TestFlight. Contributor builds leave the recorder out ([0010](decisions/0010-capture-recording-and-replay.md))
- Status overlay: `status_reports`, `status.json` and the `trusted_status_auto` publish path (its reports need `valid_until`; set the maximum duration). Evidence photos stay private, blurred server-side and time-limited
- Moderation UI as an authenticated route in `apps/web`, with `moderation_events`. Who moderates at launch is still open
- Hosting: the smallest x86 Singapore server for the Node API and PostGIS, private bundles in S3 ap-southeast-1, WAL archiving to S3 and a restore drill ([0009](decisions/0009-hosting-and-budget.md)). The privacy notice and the retention rules go live
